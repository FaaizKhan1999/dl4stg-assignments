\section*{Task 1 --- Forecasting Across Heterogeneous Sensors}

\subsection*{0. The World and Forecasting Setup}

I will use this section specifically to outline about what I interpret as the setup of the problem in this task, for my own understanding. You may skip to the next section if you would just like to read my responses to the questions asked.

There is a production line with 4 rotating production stations connected in series, labelled 1--4. Each station has one vibration accelerometer --- a physical sensor attached to the station to measure its physical movement in metres per second squared ($m/s^2$) --- sampled at 20 Hz, equivalent to 0.05 seconds per sample.

While the samples are taken at the exact time intervals regularly, the readings itself are not exactly accurate and are the sum of three components:

$$y_i(t) = b_i(t) + s_i(t) + \epsilon_i(t)$$

The above equation is station $i$'s accelerometer reading at sample $t$. The components are as follows:

\begin{itemize}
  \item $b_i(t)$: The slowly varying baseline caused by load/control conditions and sensor calibration drift. These vary on a 12-second time-scale.
  \item $s_i(t)$: The dominating, repeating physical vibration of the rotating station.
  \item $\epsilon_i(t)$: The small, independent observation noise.
\end{itemize}

The time is divided into operating runs: 192 samples per run. The first run produces product A, the second produces product B, the third produce product C, and then the process repeats. Each product has a characteristic operating-speed range, or the period of its vibration: 14--18, 21--27, and 28--36 samples respectively. This means that the cycle durations are between 0.70--1.80 seconds. At the start of each run, some factors determine one actual period within the corresponding product's range, which is shared by all 4 stations for the duration of the run.

For this task, the context length $L = 96$ and the forecast horizon $H = 48$. At forecast origin $t$, a model observes the previous $L$ readings and predicts the next $H$ readings.

$$X_i = \{y_i(t - L), \hdots, y_i(t - 1)\} \in \mathbb{R}^L, \hat{Y}_i = \{\hat{y}_i(t), \hdots, \hat{y}_i(t + H - 1)\} \in \mathbb{R}^H$$

The above would be the input and output sequences for station $i$. A forecast origin is only eligible if the entire context and target lie within an operating run: valid forecast origins for each run are from sample 96 to sample 144 (assuming zero-indexing).

The data is split into a train-validation-test split out of a total of 15360 samples. Stations 1--3 are established stations whereas station 4 is held out and serves as the unseen-station test case.

The last observed value in each context is used as the anchor which is subtracted from every single sample within that window. This means that the last sample will be 0 and forces every window to end at 0, effectively deleting any long term calibration offsets. The anchored values are scaled by the reciprocal of a single, constant scale value which is determined at the start using training data from stations 1--3 (station 4 and the validation/test regions do not contribute to this scale). This normalizes the data and compresses the amplitude so the neural network receives standardized values. The predictions are then transformed back to physical units before evaluation.

A moving average is a highly sensible inductive bias for this problem because it mirrors the physical reality of the machines: a slow baseline drift mixed with rapid, recurring vibrations. Instead of forcing the neural network to untangle a messy composite signal, the moving average acts as a low-pass filter to explicitly separate them. The oracle diagnostic was crucial here; by using known training periods, it allowed me to objectively pick the width that best isolated the true frequency.

This approach, however, will fail if the machine experiences an abrupt, instantaneous level shift, such as a physical shock or a sensor reset. Because the moving average assumes smooth, gradual changes, it would smear a sudden jump into a slope, corrupting both the extracted trend and the residual vibration signal.

\section*{Task 2 --- Leaderboard Challenge}

\subsection*{Methodology and Autoformer Architecture}

The forecasting engine uses the Autoformer architecture introduced by Wu et al. (2021). Instead of standard self-attention, it uses an Auto-Correlation mechanism that identifies temporal patterns by grouping similar historical segments based on their delays.

To handle the dataset's high volatility, I implemented several modifications to the model:

\begin{itemize}
  \item Series Decomposition: A moving-average filter splits the input into a slow-moving trend and a cyclical stream. This allows the model to explicitly isolate the trend while applying Auto-Correlation exclusively to the repeating vibrations.
  \item Reversible Instance Normalization (RevIN): Following Kim et al. (2022), the model manages extreme baseline shifts by normalizing each input window before processing and reversing the transformation after prediction. I included a tiny variance epsilon to prevent calculation errors on perfectly flat context windows.
  \item Continuous Cyclic Auto-Correlation: The model computes temporal delays efficiently using fast Fourier transforms. I also fixed a major issue in the cross-attention block: instead of padding shorter encoder sequences with zeros (which previously caused forecasts to collapse to the mean), I applied a modulo operator to force a continuous, repeating cycle.
  \item Progressive Trend \& Covariates: The decoder anchors its predicted trend to the final observed context value to prevent sudden, unnatural drops. Additionally, known future variables are injected directly into the decoder to better guide predictions.
\end{itemize}

The final model relies on 69,383 parameters and a context length of 336. It was trained for 15 epochs using MSE loss to maximize stability against heavy-tailed variance before early stopping.

\subsection*{Score Optimization and Leaderboard Submissions}

The leaderboard penalizes parameter count but heavily rewards low RMSE, so I focused on structural improvements rather than just shrinking the model.

\begin{itemize}
  \item Attempt 1 (RMSE: 116.43, Parameters: 7,938): The initial model failed, predicting a flat line. This was caused by a zero-padding bug in the cross-attention mechanism and the use of L1 loss, which mathematically forces the model to predict the median rather than tracking the high-variance spikes.
  \item Attempt 2 (RMSE: 94.83, Parameters: 57,863): I fixed the attention bug to ensure a continuous, repeating sequence. I also stabilized the normalization module to prevent calculation errors on flat context windows, increased the model dimension, and switched to MSE loss. These mathematical fixes allowed the model to accurately track the spikes, dropping the error by over 21 points.
  \item Attempt 3 (RMSE: 78.06, Parameters: 69,383): FFT-based models need sufficient historical data to resolve frequencies. I expanded the context window from 96 to 336 steps, giving the model two full operational cycles of lookback. Combined with a single decoder layer (to prevent trend over-accumulation) and a smaller batch size (to smooth out noisy gradients), this wide-context setup dropped the final RMSE to 78.06.
\end{itemize}
