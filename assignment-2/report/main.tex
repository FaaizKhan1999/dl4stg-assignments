\section*{Question 1 --- River Forecasting Proposal}

Each station attends to its upstream sources at learned, state-dependent lags, adds announced releases, and outputs level quantiles at S1--S4 for $t_0{+}10,\dots,t_0{+}60$\,min.

\subsection*{2.\ Assumptions}

\textbf{Supplied facts:} 10-min levels at S1--S4 and T1; timestamped rain at R1, R2; recorded releases and schedules with announcement and effective times; topology and river distances. Not supplied: travel times, unmonitored inflow. Unavailable at issuance: future rain and levels.

\begin{enumerate}[label=\textbf{A\arabic*}, leftmargin=*, itemsep=0pt]
  \item $\ge$3 years of data with several floods, so high-flow behaviour can be learned.
  \item Levels arrive within $\sim$20 min, rain within $\sim$30 min, and arrival times are logged, so inputs can be built from what had arrived.
  \item Gaps are short and faulty readings are detectable by range and rate checks, so masking is enough.
  \item Each rain report gives the depth since the previous one, so rain is summed per bin, not interpolated.
  \item Everything relevant to a 1-h forecast happened within the last 12\,h, which sets $H{=}72$.
  \item Flow is downstream only (no backwater), so stations attend only upstream.
  \item R1 and R2 flank the unmonitored tributary (map), so rain enters only through TU and affects only S3 and S4. Other rain is buffered by the reservoir or already visible in T1.
  \item Unmonitored inflow is mainly rain-driven, so R1 and R2 are usable proxies.
  \item Travel time varies smoothly with flow and distance on a stable channel, so learned lags generalise.
  \item Release records are accurate and schedule versions are archived, needed for leak-free training.
  \item Each station has a fixed level datum, so the model can predict change from the last level.
  \item Future rain is unknown, so it is treated as uncertainty, not an input.
\end{enumerate}

\subsection*{3.\ Forecasting task and data specification}

\[
\mathcal I(t_0)=\{r: t^{\mathrm{obs}}_r\le t_0,\ t^{\mathrm{arr}}_r\le t_0\}\cup\{\text{schedules with } t^{\mathrm{ann}}\le t_0\},
\]
\[
\text{history } j=-71..0\ (12\text{\,h}),\qquad \text{horizon } k=1..6\ \ (k{=}6:\ t_0{+}60\text{ min}).
\]
Forecasts are issued every 10 min at $t_0$ from $\mathcal I(t_0)$ only. Outputs are the quantiles $\tau\in\{0.1,0.5,0.9\}$ of the level at S1--S4.

\textbf{Alignment.}
\begin{itemize}[leftmargin=*, itemsep=0pt]
  \item \emph{Time:} levels take the last value per 10-min bin; rain depth is spread over its report interval and summed per bin; releases are step-held. Masks and ages mark gaps.
  \item \emph{Space:} no interpolation. Each source is a node (the two gauges are concatenated into TU), related only through $\mathcal U(n)$ and $d_{ij}$.
  \item \emph{Features:} per-type projections $W_c$ map every source to width $d$ before stacking on the node axis.
\end{itemize}

\subsection*{4.\ Model computations and design justification}

Notation: $\mathcal U(n)$ = upstream closure (Figure~\ref{fig:q1graph}), e.g.\ $\mathcal U(\mathrm{S3})=\{\mathrm{S3},\mathrm{S2},\mathrm{S1},\mathrm{T1},Q,\mathrm{TU}\}$; $h_{t,n}\in\mathbb R^d$ is node $n$ at time $t$. TU has no sensor, so $h_{t,\mathrm{TU}}$ is a learned rain feature, not an inflow estimate; a tributary gauge would make it a supervised node without structural change.

\begin{table}[H]
\centering
\renewcommand{\arraystretch}{1.8}
\resizebox{\linewidth}{!}{%
\begin{tabular}{@{}ll@{}}
\toprule
\textbf{Stage} & \textbf{Formulation} \\
\midrule
(a) Projection &
$z^{(0)}_{t,n}=W_{c(n)}x_{t,n}+p_n+e_t$ \\
(b) Temporal &
$h^{(\ell)}_{t,n}=h^{(\ell-1)}_{t,n}+\mathrm{MLP}\big(\sum_{j=0}^{2}W_j h^{(\ell-1)}_{t-j\delta_\ell,n}\big),\quad \delta_\ell=1,2,4,8$ \\
(c) Lag attention &
$\begin{aligned}
&\alpha_{t,j}(i,s)=\operatorname{softmax}_{i\in\mathcal U(j),\,s\le t}\tfrac{(W_Qh_{t,j})^{\top}(W_Kh_{s,i}+\phi(d_{ij},t{-}s))}{\sqrt d}\\

\end{aligned}$ \\
(d) Decoder &
$u_{k,n}\mathrel{+}=\mathrm{Attn}\big(u_{k,n};\{h_{s,i}:i\in\mathcal U(n)\}\cup\{f_{k'}:k'\le k\}\big),\quad f_{k'}=W_sx^s_{k'}+e_{k'}$ \\

$\hat y^{(0.5)}_{k,n}=\bar y_n+\sigma_n a,\quad \hat y^{(0.9)}=\hat y^{(0.5)}+\sigma_n\,\mathrm{softplus}(b),\quad \hat y^{(0.1)}=\hat y^{(0.5)}-\sigma_n\,\mathrm{softplus}(c)$ \\
(f) Loss &
$\displaystyle \mathcal L=\frac{\sum w_b\,m\,\rho_\tau(y-\hat y^{(\tau)})}{\sum w_b\,m},\quad \rho_\tau(r)=\max(\tau r,(\tau{-}1)r),\quad w_b=1+\lambda\,\mathbb 1[\text{flood}]$ \\

\caption{Model components.}
\label{tab:model}

\noindent\textbf{Why each block:}
\begin{itemize}[leftmargin=*, itemsep=0pt]
  \item[(b)] Local trends and rain-accumulation shape.
  \item[(c)] One layer reaches every upstream source at every lag (A5). Queries and keys depend on current states, so lags shift with flow (A9). $\phi$ handles uneven spacing; $\mathcal U$ encodes flow direction (A6).
  \item[(d)] Announced releases act only on steps where they are already effective ($k'\le k$).
  \item[(e)] Anchoring on $\bar y_n$ makes the model predict change from persistence (A11); softplus keeps quantiles from crossing.
  \item[(f)] A point loss gives only a mean or median. Irreducible uncertainty (tributary, future rain) needs bands; $w_b$ up-weights floods.
\end{itemize}
Training: chronological splits, as-of inputs, random masking, 5-seed ensemble, conformal calibration.

\subsection*{5.\ Operation and exceptional conditions}

\begin{center}\small
\begin{tabularx}{\textwidth}{@{}l X@{}}
\toprule
Condition & Handling\\
\midrule
(i) Missing & Value $\to$ 0 with mask $=1$ and growing age; $\bar y_n$ uses the last valid level. Training randomly drops points, blocks and whole stations. Missing targets are masked out of the loss. If all river data fail, fall back to persistence and alert.\\
(ii) Delayed & Only records with $t^{\mathrm{arr}}\le t_0$ are used; a late record counts as missing until it arrives and is used in the next 10-min cycle. Training replays history as-of each issuance with logged delays (A2).\\

\bottomrule
\end{tabularx}
\end{center}

\noindent\textbf{Feasibility.} With $L=HN=504$ tokens, even dense attention costs $2L^2d\approx3\times10^7$ MACs per layer, about $10^9$ for the 5-member ensemble: under 1\,s on a CPU, so ingestion dominates the 10-min cycle.

\subsection*{2. Motion, appearance, or both?}

All three keep the motion physically valid; they differ in what they change:

\begin{center}
\begin{tabularx}{\textwidth}{@{}l >{\raggedright\arraybackslash}X >{\raggedright\arraybackslash}X@{}}
\toprule
Transformation & Motion statistics & Digit appearance \\
\midrule
Mirror $M$ & Unchanged: directions map $\theta \to 180^\circ-\theta$, and these are already common in training. & Changed: a mirrored digit is not a real digit. \\
Rotation $R$ & Unchanged: directions map $\theta \to \theta+90^\circ$, and these are already common in training. & Changed more: rotated digits look even less familiar. \\
Speed-up $k\times$ & Changed: steps are $k$ times longer, outside the training range. & Unchanged: same digits. \\
\bottomrule
\end{tabularx}
\end{center}

\textbf{Why this is a controlled experiment.} Each transformation changes mainly one factor:
\begin{itemize}[itemsep=0pt]
  \item Mirror and rotation change only appearance, so failures there point to appearance.
  \item Speed-up changes only motion, so failures there point to motion (unfamiliar speed or limited reach).
  \item Mirror and rotation give two levels of appearance change, so we can check whether a larger change causes a larger error.
\end{itemize}
The correct answer is always known exactly ($T(Y)$ or the faster true frames).

\subsection*{3. How far can information travel in model A?}

One folded cell is 4 pixels. Only spatial convolutions larger than $1\times1$ move information; pixel (un)shuffle, the $1\times1$ head and the element-wise gate and cell updates do not. Each $3\times3$ convolution moves information by at most 1 cell:

\begin{center}
\begin{tabular}{lcc}
\toprule
Path to $\hat{x}_{\tau+1}$ & $3 \times 3$ convolutions & Reach \\
\midrule
$u_\tau \to$ layer 1 $\to$ layer 2 $\to$ output & 2 & 2 cells = 8\,px \\
$h^{(1)}_{\tau-1} \to$ layer 1 $\to$ layer 2 $\to$ output & 2 & 2 cells = 8\,px \\
$h^{(2)}_{\tau-1} \to$ layer 2 $\to$ output & 1 & 1 cell = 4\,px \\
\bottomrule
\end{tabular}
\end{center}

\textbf{Model A's reach is 8\,px per step} (2 convolutions $\times$ 1 cell $\times$ 4\,px).
\begin{itemize}[itemsep=0pt]
  \item The reach is per axis (a $3\times3$ kernel covers a square), so up to $8\sqrt2\approx11$\,px along a diagonal.
  \item Recurrence carries information further over several steps, but only 8\,px per step. A digit moving further than that leaves the region its old position (in $h^{(1)}_{\tau-1}$) can reach in one update.
\end{itemize}

\subsection*{5. Predictions before testing}

\textit{This answer was written and committed before any experiment in Testing the Baseline, and is reproduced exactly as first written.}

\paragraph{Mirror and rotation.}
I predict model A will mostly pass the mirror test and do somewhat worse on the rotation test. From Figure 1(a), all 18 directions have motion and no direction is missing or rare, so every direction that a mirrored or rotated video produces is already well represented in training. The motion itself should be familiar, and digits should still move in the correct direction. We expect any errors to come from appearance: a mirrored/rotated digit is not a real digit, but rotated digits should seem less familiar than mirrored ones. I therefore expect $C_M$ and $E_M$ only slightly above $E^{(5)}$ at 1$\times$, and $C_R$ and $E_R$ larger, with errors showing up as blurred or distorted digit shapes rather than wrong motion.

\paragraph{Speed.}
My reach estimate is 8 pixels per step per axis (2 convolutions $\times$ 1 cell $\times$ 4 pixels per cell). From Figure 1(b), motion is concentrated between 3 and 4.5 pixels per frame (median 3.32). So 1$\times$ (3--4.5 px) is well within reach. 2$\times$ (6--9 px) straddles the 8-pixel limit and is unseen in training, so I expect noticeable degradation but not complete failure. 3$\times$ (9--13.5 px) is beyond reach and unseen in training, so I predict model A breaks down at 3$\times$: digits will blur, stall or vanish instead of moving to the right place. Because the reach is per axis, diagonal motion at 3$\times$ may degrade somewhat less than motion along the axes.

\subsection*{12. Model D: design and reach}

\textbf{Design.} Model D is model A with \textbf{dilation 2} (padding 2) in the layer-2 ConvLSTM convolution; layer 1 keeps dilation 1. Everything else is unchanged: patch size 4, 64 channels per layer, one convolution for all gates, the $1\times1$ head, the 9-step rollout, and the training protocol (with speed augmentation, as for C). Dilation adds no weights, so D has \textbf{480,784} parameters (limit: 721,176). C and D therefore differ only in reach.

\textbf{Reach.} Same conventions as Q2.3; a dilation-2 convolution moves information by up to 2 cells:

\textbf{Why built-in symmetry is exact.} For $\bar f(X) = \frac{1}{8}\sum_{g\in G} g^{-1}\big(f(g(X))\big)$ and $T \in G$, substitute $g' = gT$ (so $g^{-1} = T g'^{-1}$):
\[
\bar f(T(X)) = \frac{1}{8}\sum_{g\in G} g^{-1}\big(f(gT(X))\big)
= \frac{1}{8}\sum_{g'\in G} T\,g'^{-1}\big(f(g'(X))\big) = T\big(\bar f(X)\big).
\]
$g'$ runs over all of $G$ because $G$ is a group, and $T$ (a pixel permutation) moves out of the average. So $C_M = C_R = 0$ for \emph{any} $f$; the measured $\sim10^{-16}$ is rounding. Since $T$ only permutes pixels, also $E_T = E^{(5)}$ exactly (Table~\ref{tab:6}).

\textbf{When averaging hurts.} If the base model is confident but inconsistent (sharp digits in different places per orientation), the average shows faint ghost copies. It would also force a wrong symmetry if the true dynamics were not symmetric (e.g.\ gravity). \textbf{Here it did not hurt}: every symmetrised model matches or beats its base model. The base models' $C_T$ is small next to their error, so the eight predictions mostly agree and averaging acts like a small ensemble.
